# ADR-001 — فناوری و معماری مقصد

- وضعیت: پذیرفته‌شده برای نمونه فنی؛ مشروط به اثبات در PoC
- تاریخ: 2026-11-12

## تصمیم
- Backend: C# و ASP.NET Core روی .NET 10 LTS
- Frontend: React و TypeScript
- Database: PostgreSQL
- الگو: Modular Monolith و API-first
- استقرار: Docker؛ مستقل از runtime و سرویس Floot

## دلایل
1. حفظ یکپارچگی تراکنش‌های مالی و مرزبندی روشن ماژول‌ها در Modular Monolith.
2. پشتیبانی قوی .NET از سرویس‌های سازمانی، امنیت، تست و عملیات.
3. جداسازی رابط کاربر از منطق مالی و API.
4. امکان استقرار روی سرور شخصی، VPS، ابر یا زیرساخت ترکیبی.

## محدودیت و شرط
این تصمیم به معنی اثبات سازگاری مستقیم .NET با runtime فعلی Floot نیست. Floot در وضعیت فعلی محیط serverless مبتنی بر TypeScript است. Floot فقط مرجع و محیط فعلی حفظ می‌شود؛ انتقال داده یا اتصال عملیاتی تا تکمیل PoC، بررسی backup/restore و تأیید صریح انجام نمی‌شود.

## اصول معماری
- ماژول‌ها مالک داده و قواعد دامنه خود هستند.
- وابستگی بین ماژول‌ها از قراردادهای روشن و API داخلی کنترل‌شده انجام می‌شود.
- Microservices فقط با شواهد نیاز عملیاتی، مقیاس یا استقلال استقرار بررسی می‌شود.
- محاسبات پولی با decimal و نوع‌های دقیق؛ استفاده از float/double برای مبالغ ممنوع.
- عملیات ثبت مالی باید اتمیک، متوازن، idempotent و audit-able باشد.
- AI پیشنهاددهنده است؛ مرجع حقیقت داده و قواعد قطعی سامانه‌اند.
- AI مجاز به ثبت مستقیم سند قطعی دفترکل یا اجرای عملیات حساس بدون تأیید مجاز انسانی نیست.

## پیامدها
- قبل از توسعه ماژول‌های مالی، قراردادهای هویت، tenant، audit، زمان، ارز و اعداد باید تثبیت شوند.
- .NET SDK و پایگاه داده باید در CI قابل ساخت و آزمون باشند.
- نسخه‌های runtime و SDK در مخزن pin و مستند می‌شوند.
